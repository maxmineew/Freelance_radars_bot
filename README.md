# Бот поиска лидов в Telegram-сообществах

Бот читает Telegram-каналы и чаты, находит тех, кому нужны услуги AI-студии (голосовые агенты, чат-боты,
AI-ассистенты, автоматизация), и присылает владельцу карточку лида. Сам никому не пишет и никуда не вступает.

## Как это работает

Каждый прогон проходит по шагам:

1. **Сбор.** Каналы из `sources.txt` читаются через публичную страницу `t.me/s/<канал>` без аккаунта.
   Чаты из `chats.txt` читает наблюдатель — отдельный аккаунт Telegram, только чтение.
2. **Префильтр.** Дальше идут только тексты с ключевыми словами (`KEYWORDS` в `leadbot/config.py`).
3. **Свежесть.** Посты старше 48 часов отбрасываются (статус `old`).
4. **Дубли.** Один и тот же текст в нескольких источниках оценивается один раз (статус `dup`). Так же отсеивается
   похожий текст: тот же заказ с другой шапкой или подписью (порог `SIMILAR_DUP`).
5. **Обезличивание.** Из текста убираются телефоны, почта, ссылки, @имена и ФИО.
6. **Оценка.** Модель (Groq или Gemini) решает, лид ли это, и ставит оценку 0–10. Заказ с истёкшим сроком лидом не считается.
   Вместе с постом модель получает ваши последние отметки «Беру» и «Неточно» как примеры.
7. **Карточка.** При оценке от 6 владельцу приходит карточка в Telegram.

Расписание: 09, 11, 13, 15, 17, 19 и 21:00 по Москве.

## Карточка и кнопки

В карточке: оценка, услуга, ниша, потребность, цитата-сигнал, бюджет (если указан), вариант первой фразы
и ссылка на пост. Для заказов с биржи есть отдельная ссылка на заказ.

| Кнопка | Когда нажимать |
|---|---|
| ✅ Беру | Лид подходит, вы с ним работаете. Такие записи не удаляются из базы |
| ⏭ Мимо | Лид настоящий, но вам не нужен |
| 🎯 Неточно | Бот ошибся: это не лид, реклама, устаревший заказ |

После нажатия под карточкой появляется второй ряд кнопок:

- после «Неточно» — причина: реклама, устарел, не моя услуга, не клиент. Причина попадает в примеры для модели;
- после «Беру» — этап работы: написал, ответил, сделка, отказ. Если этап не меняется сутки
  (`REMIND_AFTER_HOURS`), бот один раз напомнит о лиде. По сделке и отказу напоминаний нет.

Выбор можно поменять, нажав другую кнопку. По отметкам считается точность:
`Беру / (Беру + Мимо + Неточно)`.

Кнопки отвечают только владельцу (`OWNER_CHAT_ID`). Кнопку под старым сообщением, которую бот не узнаёт,
он убирает при нажатии.

## Команды

Команды вынесены на кнопки под полем ввода и в меню «/». Чужим бот не отвечает.

| Кнопка | Команда | Что показывает |
|---|---|---|
| 📊 Статистика | `/stats` | Карточки, отметки и точность за сегодня, 7 дней и всё время; причины «Неточно»; этапы взятых лидов |
| 📡 Источники | `/sources` | Карточки и отметки по каждому каналу и чату; источники без единой «Беру» и без карточек |
| ✅ Мои лиды | `/leads` | Последние 20 взятых лидов с этапом |
| 📬 Пришли карточки | `/cards` | Ещё раз присылает свежие карточки без отметки, до 10 за нажатие. Новых не ищет |
| ℹ️ Статус | `/status` | Последний прогон и его итог, следующий по расписанию, число источников |
| ▶️ Прогон | `/run` | Запускает прогон вне расписания и присылает итог |
| | `/help` | Справка |

Если кнопки под полем ввода пропали или изменились, увеличьте `MENU_VERSION` в `leadbot/feedback.py`
и выложите код: бот пришлёт клавиатуру заново.

## Сообщения о сбоях

Бот сам пишет владельцу, если что-то сломалось. Один и тот же сбой — не чаще раза в сутки.

| Сообщение | Что делать |
|---|---|
| Прогон упал | Журнал: `journalctl -u leadbot.service -n 50 --no-pager` |
| Наблюдатель вышел из аккаунта | Войти заново на сервере: `python -m leadbot.watcher` |
| Модель не оценила постов | Проверить ключ и лимиты Groq или Gemini. Неоценённые посты повторно не оцениваются |
| Не отправлено карточек | Ничего: такие карточки уйдут в следующий прогон |
| Ни один канал не открылся | `t.me` недоступен с сервера |
| Прогонов не было больше 5 часов | `systemctl list-timers leadbot.timer` |

## Как писать лидам и не получить ограничение

Telegram ограничивает аккаунты, которые пишут первыми многим незнакомым людям («можете отправлять сообщения
только взаимным контактам»).

- Не больше 2–3 первых сообщений незнакомым людям в день.
- Первое сообщение короткое, без ссылок, не одинаковое для всех.
- Лиду из чата сначала ответьте публично в чате, чтобы человек написал вам сам.
- Если ограничение уже есть: откройте `@SpamBot`, он покажет срок и примет апелляцию.
- Не пишите лидам с аккаунта наблюдателя: его бан остановит чтение чатов.

## Источники

| Файл | Что в нём |
|---|---|
| `sources.txt` | Публичные каналы, по одному имени в строке, без `@` |
| `chats.txt` | Чаты: `@имя` публичного чата или ссылка-приглашение |
| `chats.md` | Полная база с цифрами и причинами исключения |

Строки с `#` не читаются. После правки файлов нужно выложить их на сервер (см. «Выкладка»).

В чат по ссылке-приглашению нужно вступить вручную под аккаунтом наблюдателя. Пока аккаунт не в чате, в журнале
будет строка «пропущен, аккаунт не состоит в чате». Публичные чаты читаются без вступления.

## Настройки

Все в `leadbot/config.py`:

| Параметр | Значение | Смысл |
|---|---|---|
| `MIN_SCORE` | 6 | Минимальная оценка для карточки |
| `MAX_CARD_AGE_HOURS` | 48 | Посты старше не оцениваются и не отправляются |
| `EXCHANGE_RULES` | Kwork: оценка от 7, не старше 3 ч, до 3 в сутки | Правила для бирж с лимитом откликов |
| `MAX_AGE_DAYS` | 14 | Глубина истории при сборе |
| `PAGES_PER_CHANNEL` | 3 | Сколько страниц канала читать (около 20 постов на страницу) |
| `SIMILAR_DUP` | 0.6 | Доля общих четвёрок слов, с которой текст считается дублем более раннего |
| `REMIND_AFTER_HOURS` | 24 | Через сколько часов напомнить о взятом лиде, если этап не менялся |
| `RUN_HOURS` | 9…21 через 2 | Часы прогонов по Москве для «Статуса»; само расписание — в `deploy/leadbot.timer` |
| `CHAT_MSG_LIMIT` | 100 | Максимум сообщений из одного чата за прогон |
| `RETENTION_DAYS` | 30 | Через сколько дней записи удаляются |
| `KEYWORDS` | список | Слова префильтра |

Критерии лида для модели описаны в `SYSTEM` в `leadbot/classifier.py`; к ним добавляются примеры из отметок
(`examples` там же). Оценку делает Groq, если в `.env` есть
`GROQ_API_KEY`, иначе Gemini.

Ключи лежат в `.env`: `GROQ_API_KEY` или `GEMINI_API_KEY`, по желанию `GROQ_MODEL` / `GEMINI_MODEL`, `BOT_TOKEN`, `OWNER_CHAT_ID`, `TG_API_ID`, `TG_API_HASH`.

## Сервер

Бот работает на сервере `185.103.101.30` (Ubuntu 24.04) в каталоге `/opt/leadbot` под пользователем `leadbot`.
Время на сервере — UTC, то есть Москва минус 3 часа.

| Служба | Назначение |
|---|---|
| `leadbot.timer` | Расписание прогонов |
| `leadbot.service` | Один прогон; между запусками в состоянии `inactive` — это норма |
| `leadbot-feedback.service` | Постоянный слушатель: кнопки карточек, команды, напоминания. Очередь обновлений Telegram читает только он |

Частые команды (после `ssh root@185.103.101.30`):

```bash
systemctl list-timers leadbot.timer          # когда следующий прогон
systemctl is-active leadbot.timer leadbot-feedback.service
journalctl -u leadbot.service -n 50 --no-pager   # журнал последних прогонов
systemctl start leadbot.service              # прогон вне расписания (или кнопка «Прогон» в боте)
```

Два прогона одновременно не идут: второй запуск завершается со строкой «Прогон уже идёт». Прогон, запущенный
кнопкой, пишет в журнал слушателя: `journalctl -u leadbot-feedback.service`.

## Выкладка

Из Git Bash, из папки проекта:

```bash
bash deploy/deploy.sh root@185.103.101.30
```

Скрипт копирует код, `sources.txt`, `chats.txt` и `.env` (без пароля от хостинга), ставит зависимости
и перезапускает службы. Пароль сервера спросит два раза.

- Не выкладывайте во время прогона: сначала проверьте, что `leadbot.service` в состоянии `inactive`,
  а «Статус» в боте не пишет «Сейчас идёт прогон». Выкладка обрывает прогон, запущенный кнопкой,
  и следующий час новые прогоны будут пропускаться.
- База `leads.db` и сессия `watcher.session` на сервере не перезаписываются: в них отметки и кеш чатов.

## Чего нельзя делать

- **Запускать `run.py` на своём компьютере.** Одна сессия наблюдателя с двух адресов — риск блокировки аккаунта.
  Задача `LeadBot` в Планировщике Windows по этой причине отключена.
- **Копировать на сервер локальные `leads.db` и `watcher.session`.**
- **Вступать в чаты или писать с аккаунта наблюдателя** сверх необходимого.
- **Запускать слушатель (`python -m leadbot.feedback`) на своём компьютере.** Он заберёт нажатия и команды
  у слушателя на сервере.

Проверка без отправки карточек — только на сервере: `python run.py --dry` печатает карточки в консоль.

## Персональные данные (152-ФЗ)

- Авторы сообщений не сохраняются.
- В модель (Groq или Gemini) уходит только обезличенный текст.
- В базе хранятся ссылка на пост, дата, оценка, карточка, ваши отметки и два отпечатка текста для поиска дублей
  (хеши; текст по ним не восстановить). Сами тексты не хранятся.
- Примеры для модели берутся из карточек (ниша, потребность, обезличенная цитата), а не из текстов постов.
- Записи старше 30 дней удаляются автоматически, кроме отмеченных «Беру».

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| Нет карточек | Журнал прогона. Чаще всего подходящих постов просто не было: смотрите строки «Новых постов после префильтра» |
| Кнопки и команды не отвечают | `systemctl is-active leadbot-feedback.service`, при необходимости `systemctl restart leadbot-feedback.service` |
| «Прогон уже идёт», хотя прогона нет | Прошлый прогон оборвался. Через час после его начала запись перестаёт мешать |
| «пропущен, аккаунт не состоит в чате» | Вступить в чат вручную под аккаунтом наблюдателя или дождаться одобрения заявки |
| «нет входа в аккаунт» | Сессия наблюдателя слетела: войти заново командой `python -m leadbot.watcher` |
| Приходят старые заказы | Значение `MAX_CARD_AGE_HOURS`; отмечайте такие карточки «Неточно» |
| Слишком много или мало карточек | `MIN_SCORE` и список `KEYWORDS` |

Статусы записей в базе: `new` (ждёт оценки), `skipped` (не прошёл префильтр), `scored` (оценён), `sent` (карточка
отправлена), `dup` (дубль), `limit` (не прошёл правила биржи), `old` (устарел).
